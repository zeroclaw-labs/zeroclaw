クイックスタート

クイックスタートは、新規インストールから動作するエージェントまでを一度の操作で導く、ガイド付きセットアップです。これは3つのインターフェイス上で動作します。CLI、zerocode ターミナルインターフェイス、そして web gateway です。3つはすべて同じ基盤フローを動かすため、生成される設定は同一です。今いる環境に合ったものを使用してください。

インストール

Unix の高速パス

curl -fsSL https://raw.githubusercontent.com/zeroclaw-labs/zeroclaw/master/install.sh | sh

このルートは非対話型で、ピッカーを開きません。

一致するビルド済みバイナリを優先し、必要に応じてソースからのビルドにフォールバックします。

ビルド済みアーカイブには zerocode が含まれている場合があります。非対話型のソースフォールバックでは、ピッカーを開かずにデフォルトアプリがインストールされます。

このコマンドでは固定の機能セットが使用されます。

ソースからのビルドが必要な場合、インストーラーは Rust がインストールされていなければ Rust をブートストラップできます。

Unix では、許可されている場合、インストーラーがシェルプロファイルを更新します。新しい PATH を利用する前に、親シェルを再読み込みしてください。

インストーラーはセットアップをスキップし、次の手順として zeroclaw quickstart を表示します。

Unix ガイド付きパス

git clone https://github.com/zeroclaw-labs/zeroclaw.git
cd zeroclaw
./install.sh

このルートはガイド付きで、サポートされている選択肢が提示される場合があります。

サポート対象のターゲットでは、ビルド済み版またはソースからのインストールを利用できます。

ビルド済みアーカイブには zerocode が含まれている場合があります。ソースを選択すると、zerocode がデフォルトで選択され、アプリを選択できます。

ソースパスでは、オプションの Cargo フィーチャーも選択できます。

ソースからのビルドが必要な場合、インストーラーは Rust がインストールされていなければ Rust をブートストラップできます。

Unix では、許可されている場合、インストーラーがシェルプロファイルを更新します。新しい PATH を利用する前に、親シェルを再読み込みしてください。

未設定のインストールでは、zeroclaw quickstart またはブラウザーベースのクイックスタートを利用できます。

Windows のビルド済みパス

Windows セットアップガイドの PowerShell ブロックを使用してください。インストールと PATH の設定は冪等で、Quickstart は引き続き実行されます。

このルートは非対話型で、ピッカーを開きません。

この方法では、ビルド済みのリリースアーカイブをインストールします。

アーカイブには zerocode も含まれている場合があります。利用できるかどうかはリリースアセットによって異なります。

このコマンドでは固定の機能セットが使用されます。

このビルド済みルートでは、Rust ツールチェーンは必要ありません。

Windows では、PowerShell のパスにより、現在のプロセスと永続的なユーザー PATH が更新されます。

PowerShell ブロックは、最後に zeroclaw quickstart を自動的に実行して終了します。

Windows

cargo install --locked --path .

このルートは非対話型で、ピッカーを開きません。

この方法では常にソースからビルドされます。

このコマンドはコアの zeroclaw バイナリをインストールします。オプションのアプリはインストールしません。

このコマンドでは固定の機能セットが使用されます。

このコマンドを使用する前に Rust ツールチェーンが必要です。

この Cargo コマンドは PATH を編集しません。Cargo の bin ディレクトリがすでにシェルで利用可能になっていることを確認してください。

インストール後、zeroclaw quickstart を実行します。

手順

重要: これらの用語に馴染みがない場合は、まず Getting Started → Concepts をお読みください。モデルプロバイダー、リスクプロファイル、エイリアスなどの用語がすべて定義されています。

すべてのサーフェスは同じチェックリストを順に進め、同じ設定を書き込みます。ただし、任意の「Plugins」ステップは現時点では CLI のみで利用できます。必須ステップが完了するまではエージェントを作成できず、任意ステップはスキップできます。

ステップ必須設定内容
モデルプロバイダーyesプロバイダーファミリー（Anthropic、OpenAI、Ollama、OpenRouter、…）、その API キーまたはエンドポイント、およびモデル。
リスクプロファイルyes自律性とサンドボックスの設定。プリセットを選択するか、既存の [risk_profiles.<alias>] を再利用します。
メモリyesメモリバックエンド（sqlite、markdown、postgres、qdrant、lucid、または none）。
チャネルoptionalチャットプラットフォーム（Telegram、Discord、Slack など）。組み込みの cli チャネルは常に利用可能です。その他のチャネルはここで、または後から追加できます。
ピアグループoptional設定したチャンネルのマルチエージェントピアメンバーシップ。
プラグインoptionalツールプラグインはプラグインレジストリから提供され、エージェント作成時にインストールおよび設定されます。plugins-wasm を有効にしてビルドした場合にのみ利用可能で、現時点では CLI クイックスタートでのみサポートされています。詳細は プラグイン を参照してください。
エージェントyesエージェントのエイリアス、システムプロンプト、その他の性格ファイル。

ランタイムプロファイルは自動的に設定されます。Quickstart は新しいエージェント用に unbounded プリセットをインストールします。後から [runtime_profiles.<alias>] を編集して、予算とタイムアウトを調整してください（リファレンス → 設定 を参照）。

CLI

ヘッドレスマシン上やSSH経由での最速の方法:

sh

zeroclaw quickstart

ターミナルで1ステップにつき1つのプロンプトに応答します。組み込みの cli チャネルはすぐに動作するため、Channels と Peer groups はスキップできます。すべてデフォルトで承認なしの設定については、YOLO mode を参照してください。

OpenAI Codex サブスクリプション認証

クイックスタートでは、APIキーなしでOpenAI Codexのサブスクリプションパスを設定できます。一度認証したら、プロバイダーとしてOpenAIを選択し、プロンプトが表示されたらAuthenticationをcodexに設定してください:

# すでに Codex CLI でサインインしている場合:
zeroclaw auth login --model-provider openai-codex --import ~/.codex/auth.json

# または ZeroClaw 独自の OpenAI Codex ログインフローを開始します:
zeroclaw auth login --model-provider openai-codex

スクリプト化されたセットアップでは、openai-codex はクイックスタート入力のエイリアスとして受け付けられ、正規の [providers.models.openai.<alias>] エントリを書き込みます:

zeroclaw quickstart --model-provider openai-codex --model gpt-5.4 --agent assistant

Claude サブスクリプション setup-token 認証

クイックスタートでは、通常の Console API キーまたは Claude Max で生成されたトークンを使用して、Claude/Anthropic を設定することもできます。

claude setup-token
zeroclaw quickstart --model-provider anthropic --model claude-sonnet-4-5 --agent assistant

Anthropic を選択し、認証 を setup_token に設定してから、claude setup-token からのトークンを API キー/トークンのプロンプトに貼り付けます。スクリプト入力ではエイリアスとして --model-provider claude を使用できます。Quickstart は引き続き正規の [providers.models.anthropic.<alias>] エントリを書き込みます。トークンは api_key と同じクレデンシャルパスに保存されます。

プラグイン

ビルド時に WASM プラグインのサポートを有効にした場合、CLI チェックリストの Peer groups の後にオプションの Plugins 行が追加されます。この行は、バイナリが plugins-wasm 機能を有効にしてビルドされた場合にのみ表示されます。現在のリリースアーカイブはこの機能なしでビルドされているため、そのチェックリストには Plugins 行がありません。--preset full を指定したソースビルドと all-features コンテナイメージには含まれます。現時点で行を提供しているのは CLI クイックスタートのみで、zerocode およびウェブゲートウェイのクイックスタートにはまだプラグインが記載されていません。この行を未訪問のままにしても、何も変わりません。

この行を開くと、zeroclaw plugin search が使用するものと同じプラグインレジストリのインデックスを取得し（別のレジストリを使うには ZEROCLAW_PLUGIN_REGISTRY_URL を設定）、レジストリが提供する、またはこのマシンに既に存在するすべてのツールプラグインを一覧表示します。インストール済みのものには印が付きます。レジストリインデックスを取得できない場合は、再試行するか、プラグインなしで続行できます。プラグインを選択してもパッケージはダウンロードされず、設定も変更されません。行を開くだけでは、zeroclaw plugin search と同様に、データディレクトリ配下にレジストリインデックスのキャッシュを書き込み、plugins ディレクトリが存在しない場合は作成します。

設定ファイルの [plugins] セクションを Quickstart が読み取れなかった場合（そのセクションまたはファイル全体が不正な形式である場合）、レジストリを取得する代わりに、その行にその旨が表示されます。選択できる項目は提示されず、Create はプラグインをインストールしません。ファイルを修正してから、Quickstart を再度実行してプラグインをインストールしてください。

設定ファイルが古い ZeroClaw バージョンで作成されている場合、Create はプラグインのインストールやエージェントの作成を行う前に停止し、zeroclaw plugin bind と同様にファイルを更新する zeroclaw config migrate コマンドを表示します。そのコマンドを実行してから、Quickstart をもう一度実行してください。古いファイルにプラグイン設定を保存すると、移行されていない古い設定を残したままファイルが最新扱いになり、後続の実行でその設定が読み込まれなくなります。

When you choose Create, Quickstart installs the picked plugins before it creates the agent. First it checks the rest of your choices, and the configuration they land in, the way the agent step will, including the authorization check the agent step runs before it writes anything. If the agent step would refuse them, for example because a permission profile names an agent that no longer exists, Quickstart reports the problems and stops before any plugin is downloaded or written. Then it installs the plugins one at a time, through the pipeline zeroclaw plugin install uses:

  1. It resolves the package from the registry and refuses a registry entry that has no sha256 digest for its archive, before requesting the archive. zeroclaw plugin install checks the digest only when the registry lists one; Quickstart requires it.

    x-secret が付与されたプロパティは、入力中にマスクされます。また、シークレットの値の前後にあるスペースや改行は、zeroclaw config set と同様に削除されます。

    一覧から選択した値は、スキーマに記載されたとおりに、空文字列を含めて保存されます。一方、入力欄を空のまま確定すると、任意の設定は未設定のままになります。

    値は何かを書き込む前にスキーマに照らして検証されます。検証に失敗した場合は、もう一度だけ入力できます。それでも失敗すると、Quickstart は設定なしでプラグインをインストールするかどうかを尋ねます。

    シークレットであるか一覧から選択する必須の設定で Esc を押すと、そのプラグインはスキップされます。

    Quickstart は、名前がポータブルキー文法（ASCII の英字、数字、.、-、_ からなる最大 128 文字）に従うプロパティに対してのみ入力を求めます。それ以外のプロパティは名前を表示するので、後から zeroclaw config set で設定できます。

    必須のプロパティが、ポータブルキー文法に従わないものである場合、またはスキーマが宣言せずに必須としている名前である場合、どの入力も検証を通過できません。そのため Quickstart は設定を求めず、設定なしでプラグインをインストールするかどうかを直接尋ねます。

    スキーマが宣言していない名前を必須としている場合、zeroclaw config set が何を書き込んでも、どの設定エントリもその要件を満たすことはできません。そのため、この質問ではプラグインのツールは使用できないことを伝えたうえで、それでもインストールするかどうかを尋ねます。

  7. zeroclaw plugin install と同じトランザクションでパッケージを公開し、その設定エントリを初期化します。その後、zeroclaw config set と同じ方法で設定を保存します。エントリの初期化に失敗した場合、トランザクションはパッケージを削除します。その削除にも失敗した場合、Quickstart はプラグインがまだインストールされていることを表示し、そのための zeroclaw plugin remove コマンドを出力します。設定の保存に失敗した場合、プラグインはインストールされたままとなり、Quickstart は設定ごとに、値の入力を求める zeroclaw config set コマンドを出力します。チャネルも提供するプラグインには、zeroclaw plugin install がそのプラグインについて出力する内容が表示されます。すなわち、インスタンスをバインドする zeroclaw plugin bind コマンド、または、そのパッケージを既にバインドしているエイリアスの準備状態です。Quickstart 自体はチャネルインスタンスをバインドしません。

x-secret が付いていない設定に入力した値はプロンプトに表示され、スキーマのデフォルト値がそこに事前入力されます。設定値がログや Quickstart が出力するステータス行に書き込まれることはありません。ステータス行には設定名のみが記載されます。

既にインストールされているプラグインは、再ダウンロード、アップグレード、設定の再入力は行われません。Quickstart は設定エントリが存在しない場合にのみ、そのエントリを作成します。新しいエントリは新たな権限付与にあたるため、http_client を要求し宛先を宣言しているプラグインについては、まずプラグインの内容を確認し、新規インストールと同じ選択を行います。すなわち、宣言された宛先への通信を許可する、ネットワークアクセスなしでエントリを作成する、またはスキップする、のいずれかです。スキップした場合はエントリは作成されず、後でエントリを作成するためのコマンドが表示されます。そのコマンドはネットワークアクセスなしでエントリを作成します。宣言された宛先への通信を許可するコマンドは単独の行に表示され、前のコマンドの後に実行します。したがって、表示されたコマンドを実行しても、拒否した許可が付与されることはありません。その他の不足しているエントリは、zeroclaw plugin install が初期値を設定する方法と同じ方法で作成されます。既存のエントリは、インストール済みプラグインに属するものでも、以前のインストールから残されたものでも、決して変更されません。そのため、外部通信の許可と設定は現状のまま維持されます。同じ選択で Quickstart を再度実行しても、何もダウンロードされず、それらのエントリは変更されません。

既にインストールされているプラグインのセットアップを Quickstart が完了できない場合（例えば、設定に依然としてパッケージ名のみで命名された 1.0 より前のエントリが残っている場合や、新しいエントリの保存に失敗した場合）、そのプラグインについては何も書き込まず、プラグインはインストールされたままであることと、その理由を表示します。

最後のプラグインの後、選択したプラグインが1つ以上インストールされていて、plugins.enabled または plugins.auto_discover がオフの場合、Quickstart はプラグインの有効化を行うかどうかを一度だけ確認します。確認の前に、変更される設定と、その結果有効になるものの一覧を表示します。一覧には、今回の実行より前にインストールされたものを含め、インストール済みのすべてのツールおよびスキルプラグインが含まれます。plugins.enabled がオフの場合は、有効になっているすべての [channels.plugin.<alias>] チャネルも含まれます。この一覧は、デーモンが次回起動時に読み込むのと同じ方法でプラグインディレクトリから読み取られるため、インストールの失敗を元に戻せなかったプラグインも含まれます。署名が検証されていない一覧内の各プラグインには、手順4の署名行が続きます。今回の実行で選択していないプラグインも同様です。

回答は、一覧が今回の実行でインストールまたは保持したプラグインと一致する場合はデフォルトで「はい」になります。有効になるものがそれ以外を含む場合はデフォルトで「いいえ」になります。それには、設定エントリが不足しているためスキップすることを選んだインストール済みプラグインや、Quickstart がセットアップを完了できなかったプラグインが含まれます。プラグインディレクトリを読み取れない場合、Quickstart は一覧が不完全な可能性があることを表示し、回答のデフォルトは「いいえ」になります。拒否すると、両方の設定は変更されず、後で有効にするための zeroclaw config set コマンドが表示されます。両方の設定がすでにオンの場合は、確認は行われません。

エージェントの作成後、Quickstart は選択された各プラグインのうち、インストール済みのものの状態を表示します。状態には、ツールとして採用されたかどうかと設定エントリのキー、または採用されなかった理由が含まれます。理由としては、plugins.enabled や plugins.auto_discover が無効になっている場合や、plugins.max_active_instances の上限に達している場合などがあります。プラグインは、その設定エントリがランタイムの各呼び出しで適用される設定チェックに合格した場合にのみ、採用済みと報告されます。

採用済みであっても、まだ登録されたわけではありません。ツールレジストリは次回の構築時にプラグインを登録しますが、既に登録されているツール（組み込みツールなど）と名前が衝突するパッケージや、ツールの説明を読み取れないパッケージは、引き続き登録を拒否します。ランタイムのログには、こうした拒否が記録されます。

設定チェックに失敗した場合（例えば、必須の設定を指定せずにプラグインをインストールした場合）は、状態にチェックが示す理由が表示され、不足している必須の設定名と、各値を設定するための zeroclaw config set コマンドが示されます。Quickstart が表示するコマンドは、移植可能なキー文法に含まれる設定名に対するものだけです。これらは安全に表示でき、シェルに貼り付けることもできます。それ以外の名前の必須設定は、コマンドなしで名前だけが示されます。その場合は設定ファイルで設定するか、自分で引用符を付けた zeroclaw config set コマンドを使って設定してください。プラグインのスキーマで宣言されていない必須の名前も示されます。プラグインの発行元がスキーマを修正するまで、どの設定エントリもそのスキーマを満たせないためです。

設定エントリが存在しないプラグイン（例えば、作成をスキップした場合）も、有効として報告されません。zeroclaw config set は既存のエントリしか変更しないため、その場合は代わりにエントリを作成するコマンドが表示されます。このコマンドはネットワークアクセスを許可しません。http_client を要求し、宛先を宣言しているプラグインの場合は、エントリの作成後にそれらの宛先を許可するコマンドが別の行に表示されます。

設定に、パッケージ名のみで名付けられた 1.0 より前のプラグインのエントリが残っている場合は、どちらのコマンドも表示されません。新しいエントリを古いエントリの横に作成すると、古いエントリの設定とネットワーク許可が残ってしまうためです。代わりに、古いエントリをリネームすべきインスタンスキーが示されます。zeroclaw plugin list がそのエントリの更新手順を表示する場合（http_client を要求するプラグインで、デプロイ環境がすべてのプラグインのネットワーク許可を拒否していない場合に表示されます）は、状態にそのコマンドも示されます。そのコマンドの手順には、リネーム後のエントリに必要なネットワーク許可が含まれます。

設定すべきものがなく、ネットワークアクセスも不要なプラグインには、設定エントリは不要です。

A選択されたプラグインが既にインストール済みの場合、読み込みチェックを通過していない可能性があります。たとえば zeroclaw plugin install --no-verify でインストールされた場合がこれに当たります。そのため Quickstart は、プラグインを報告する前に zeroclaw plugin info が実行するチェックを実行します。プラグインがこのホストで読み込めない場合、ZeroClaw は起動時にそのプラグインをスキップします。その際、ステータスは「アクティブ」ではなく読み込めなかったことを示し、原因を確認するための zeroclaw plugin info コマンドを案内します。

Quickstart は設定ファイルを書き込みますが、実行中のデーモンには通知しません。すでに実行中のデーモンは読み込んだ設定を保持し続けるため、Quickstart の実行で書き込まれた設定エントリ、設定値、ネットワーク許可、プラグイン有効化の変更は、デーモンが再起動するか設定を再読み込みするまで反映されません。デーモンが読み込んだ設定でプラグインの有効化がすでにオンになっている場合、新しくインストールされたプラグインは、ツールレジストリを構築する次のタイミング（例: 新しいセッションの開始時）でより早く読み込まれることがあります。その場合、デーモンはそのプラグイン用に読み込んだ設定エントリを使ってプラグインを実行し、今回の実行で書き込まれたエントリは使用しません。読み込んだエントリがない場合、プラグインには設定値もネットワーク許可もありません。zeroclaw plugin remove が以前のインストールから残した古いエントリのように古いエントリが存在する場合は、そのエントリの設定値とネットワーク許可が適用されます。ステータスは、同じ設定ディレクトリを指定した zeroclaw service restart コマンドで締めくくられます。このコマンドは、インストール済みサービスとして実行されているデーモンを再起動します。zeroclaw agent やその他のワンショットコマンドは、次回起動時に変更を反映します。

プラグインステップでは、Ctrl+C の動作が場所によって異なります。シークレット設定では Esc と同じように動作します。必須設定では、そのプラグインの設定がキャンセルされ、プラグインはスキップされます。任意設定では、その設定は未設定のままになります。その後、Quickstart は処理を続行します。ステップ内のそれ以外の場所では、Ctrl+C を押すと、それまでに行った処理の概要を表示せずに、Quickstart が即座に終了します。インストールが完了したプラグインは、インストール済みかつ設定済みの状態のままとなり、zeroclaw plugin list に表示されます。インストール後、設定エントリが書き込まれる前に中断されたプラグインは、エントリがないままインストール済みの状態となります。同じプラグインを選択して Quickstart を再実行すると、そのエントリが作成されます。その際、ネットワーク宛先を許可するかどうかを先に確認されます。

エージェントのステップが、プラグインのステップで何かが変更された後も失敗した場合、Quickstartは何も変更されなかったとは主張しません。インストール済み、設定済み、または有効化されたままのプラグインを明示し、実行中にインストールされた各プラグインについて zeroclaw plugin remove コマンドを表示します。インストールの失敗を元に戻せず、そのためプラグインディレクトリに残ったものも含みます。Quickstartを再度実行しても、それらは再インストールされません。

アーキテクチャロードマップ（FND-001、RFC #5574、成果物 D4）では、zeroclaw onboard でプラグインをインストールできるようにすることが求められています。zeroclaw quickstart は、zeroclaw onboard が案内する現在の推奨コマンドであり、プラグインサポートを有効にしたビルドにおいてツールプラグインのインストールを提供します。オンボーディング中のチャンネルプラグインのインストールと、プラグインサポート付きのリリース成果物の提供は、別の成果物です。

Webゲートウェイ

デーモンが実行されている状態で、ブラウザでダッシュボードを開きます:

sh

zeroclaw daemon

zeroclaw daemon はランタイム全体を実行します。ゲートウェイ、設定済みのチャネル、スケジューラ、およびハートビートモニターが含まれます。（HTTPゲートウェイのみが必要な場合は、zeroclaw gateway でHTTPゲートウェイだけを起動できます。）

Webフォームでは同じ手順をカードとして表示します。送信すると、デーモン経由で入力内容が適用され（POST /api/quickstart/apply）、無効な箇所があれば構造化されたエラーリストが返されます。その後、デーモンがその場で再読み込みされ、再起動せずに新しいエージェントが有効になります。別のPOST /api/quickstart/validateエンドポイントは、適用せずに同じチェックを実行するため、先に検証したいクライアント向けです。
