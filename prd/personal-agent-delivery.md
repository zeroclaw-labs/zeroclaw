# Personal Agent 附录 B：技术验证候选值与交付拆分

适用版本：v0.6。[PRD 正文](personal-agent-prd.md)是产品规则来源，[附录 A](personal-agent-acceptance.md)是验收索引。以下为尚未冻结的工程候选值，不是已验证能力；在模型、部署及负载确认后通过技术设计冻结，变更时同步更新验收基线。正文的复核宽限期、接待窗口、删除保留期属于需评审的产品策略，不混作硬件配置。

## B1 候选测试基线

| 项目 | 候选值 | 冻结前需回答 |
|---|---|---|
| 硬件 | 4 核 CPU、16 GiB 内存、无独立 GPU、单实例 | 实际可运行的模型、量化、上下文长度及版本是什么？ |
| 资料负载 | 文本总量 10 MiB，单条 100 KiB | 五人授权上限由正文规定，不是可调整的负载参数；需测试容量与索引开销及超限提示 |
| 执行及排队 | 一个运行槽，5 个等待槽 | 槽数须支持正文最多 5 人的每人首个保留位，低于已授权人数不可启用；按人轮转；单人第二位仅用额外剩余容量。实施设计从启动起为全部五个访问者位置保留首位，未授权位置也不借用；因此默认五等待槽下，每人最多一个等待任务，不能将“最多两个”理解为试点可连发两条排队。第二等待位仅在配置超过五个等待槽时可用；冻结候选值时负责人须连带确认该限制，多设备共用人的额度 |
| 页面及持久化 | P95 ≤2 秒；处理中反馈 ≤1 秒 | 固定网络和样本数，不包含模型生成 |
| 答疑总期限 | 60 秒，从提交含排队、检索、一次生成、确定性检查至正文可见 | 无第二次同步语义模型调用；本地模型不能达标时调整模型或公开期限，重新评审体验 |
| 性能分解 | 记录排队、检索、模型首 token、完整生成、同步检查、用户可见耗时 | 模型首 token 不是用户首字；语义正确性在离线评测及异步抽检中验证 |
| 邀请／登录 | 邀请 10 分钟单次有效；访问者浏览器凭证绝对期限 30 天 | 安全会话存储、密钥轮换、撤权生效与重新批准流程 |
| 所有者登录 | 绝对期限 8 小时，显式登出及全设备撤销 | 区分进程级 admin token 与 operator Bearer；原始及派生凭证统一到期，不能只过期 Cookie；不假定现有配对原生支持 TTL |
| 答疑输入及频率 | 每条最多 4000 个 Unicode 字符且 UTF-8 最多 16 KiB；每访问者滚动 60 秒最多 6 次、每实例最多 20 次 | 多设备合并，同一问题的幂等重试不重复扣额；在入队与模型调用前校验，超限反馈限额和重试时间，拒绝正文不入日志 |
| 提示词预算 | 使用实际模型 tokenizer，系统与工具最多 2048 token、当前问题最多 2048、检索最多 2048、历史最多 1024、输出预留 1024，总预算 8192 | 需验证所选模型上下文至少 8192；当前问题若超 token 额度明确拒绝，不静默截断。字符与 token 双限同时适用；试点记录通过字符校验但被 token 拒绝的比例，并测试长中文输入；冻结前决定是否下调 CJK 字符上限或在前端提前提示／估算 token（服务端实际 tokenizer 仍是权威），不得让用户误以为字符未超限就必然可提交。资料按完整片段择取，历史裁剪对用户可见，权限规则不能被截掉 |
| 申请限流 | 每来源地址每分钟 5 次，每实例最多 100 个待批准申请 | 可信代理地址解析、滥用控制及内网共享地址误限流 |

公平性是正文要求，具体调度实现不是唯一方案。已有运行任务不抢占；每人最多一个运行和两个等待，第二等待位不得侵占别人的首位保留。超额立即拒绝，不用排到必然超时的长队伪装可用。服务端记录的等待期限和容量提示须与公开值一致。冻结前测试五人同时到达、长任务、取消、超时、连发及跨设备场景。

## B2 工作包与依赖

| 工作包 | 交付边界 | 前置依赖 |
|---|---|---|
| 身份与入口 | 所有者认证／恢复、同事身份、设备批准、权限校验、撤权及加密访问 | 冻结部署、身份流程和证书交付方式 |
| 共享知识 | 发布版本、复核、失效反馈、撤回与索引过滤 | 身份与入口 |
| 受限答疑 | 独立提示词／会话、检索、引用校验、指令隔离和语义评测集 | 共享知识、固定模型基线 |
| 请求闭环 | 类型表单、幂等提交、状态机、收件箱和请求者验收 | 身份与入口 |
| 触达与接待门控 | 内外网邮件适配、验证、汇总、重试、暂停及恢复 | 请求闭环、可用邮件服务 |
| 试点验证 | 删除、越权、故障、性能及净收益记录 | 上述工作包全部达到 P0 验收 |

进入实现前还需产出接口／错误码、页面及异常交互、持久化迁移与删除方案、具体模型／证书／邮件接入设计及估时。这些实现产物应引用本 PRD 的规则，不另创相冲突的状态或权限来源。本文不承诺尚未评估的工期。

## B3 仓库交付约束

Rust 运行时 CLI、工具及引导文案使用 zeroclaw_runtime::i18n::{get_required_cli_string, get_required_cli_string_with_args} 的 Fluent 契约；Web 文案遵循 web/src/lib/i18n.ts，不能在 Web 中误用 Rust helper；若涉及 zerocode，使用其独立 catalogue。将字符串键、英文源文案与本地化校验纳入工作包，不将裸字符串原型直接交付。

这批中文 PRD 属于 prd/ 下的评审材料，不能直接移动到 docs/book 正式文档树。正式文档先按英文源文档及仓库本地化流程补齐，再生成或更新译文，不手改生成翻译。实现前需准备文案／文档交付清单与上述检查证据。首版不实现请求回复精细引用编辑器；如后续引入，须重新评审删除边界、存储及验收。
