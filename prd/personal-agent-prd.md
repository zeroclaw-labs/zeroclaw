# Personal Agent 产品需求文档（PRD）

**版本：** v0.6 · 可评审需求稿  
**日期：** 2026-10-25  
**产品定位：** 在局域网内，代表个人提供知识答疑、接收协作请求，并在授权范围内与同事沟通的个人代理。

> 本文将“知识答疑 + 请求接待”作为首版建议范围，尚待确认。局域网通信是首版部署边界；是否允许使用云端模型需要独立配置。本 PRD 不预设 ZeroClaw 已具备相关能力。
>
> 本版澄清提问重试术语、自然到期清理、通知导航和所有者再认证路径；技术候选值仍需试点验证。正文是产品规则来源；验收见附录 A，工程候选参数及工作包见附录 B。工程参数未经冻结不构成性能承诺，产品默认值也需试点负责人确认。

## 术语

| 术语 | 定义 |
|---|---|
| 所有者 | 被代理的个人，拥有发布知识、批准访问与处理请求的权限 |
| 访问者 | 经所有者确认身份的同事；身份绑定人，访问凭证绑定设备上的浏览器会话 |
| 消息／问答轮次 | 一条发送内容／一次提问及其回答；同一问题重试不作为新的指标样本 |
| 会话 | 同一访问者与同一对外代理的连续对话容器，可包含多个问答轮次，不跨访问者共享 |
| 共享资料 | 所有者主动发布的内容及版本；不包含私人记忆和未发布草稿 |
| 来源 | 可定位到共享资料版本和片段的引用，以 source_id、版本及片段位置标识 |
| 待复核 | 超出复查期限或被报告可能失效，表示尚未确认当前有效，不等于已证实错误 |
| 请求 | 访问者确认提交的独立协作事项，有唯一编号、状态和处理记录 |
| 本人离线／服务离线 | 本人暂不查看消息／承载代理的设备或进程不可达，二者分别展示 |

## 1. 产品背景

团队反复找具体的人询问资料、操作步骤和协作安排，等待回复并来回补充背景，打断个人工作。代理用本人明确开放的知识答疑，收集需本人处理的请求，清楚说明授权边界。

## 2. 产品范围

### 2.1 目标

减少重复沟通带来的打断，同时保持本人对披露和承诺的控制。验证同事能否独立获得可信答案、请求是否足够完整，以及所有者节省时间是否超过维护纠错成本。

### 2.2 非目标

首版不自动接受任务、承诺交期或发表立场，不自主协商分工，不扫描局域网或默认读取私人消息／文件，不执行代码及修改外部业务系统，不替代聊天和任务系统。系统按本人绑定的规则发送最少元数据通知，不赋予模型任意外发权限。

## 3. 目标用户

首批建议为知识密集的研发小团队：所有者减少重复答疑，同事快速获取信息并提交完整请求，试点负责人依据净收益判断是否推广。

## 4. 核心场景

| 场景 | 行为 | 成功标准 |
|---|---|---|
| 工作答疑 | 同事询问开发步骤，代理用共享资料回答并附来源及确认日期 | 能核验并使用；无依据时明确转交 |
| 请求接待 | 同事发起评审，代理收集背景并经请求者确认提交 | 本人无需再追问基本信息；接收不等于接受任务 |
| 本人处理 | 本人接受、拒绝或要求补充，提交结果后请求者验收 | 双方能辨别处理进度与责任 |

### 本人离线时提供服务

当本人暂时不处理消息、但代理设备仍在线时，Agent 继续提供授权答疑和接待。 设备不可达时，访问端在连接失败或超时后明确提示服务不可用；未获持久化确认的请求不得显示提交成功。

接待请求的前提是所有者已验证兜底通知渠道，并设置接待状态。访问页展示“接待中／暂停接待”、服务可达状态和预计首次处理窗口；预计窗口不是任务完成承诺。默认首次处理窗口为进入待本人处理后 24 小时，按自然时间计算。窗口起点与当时公开的时长记录在请求中，调整接待安排不追溯改写已有请求期限。

超过公开处理窗口后，请求详情及列表展示“已超过预计处理窗口，本人尚未处理”，并提供复制摘要入口；提示不代表拒绝，不改变请求状态，不依赖邮件成功或请求待处理滞留满 72 小时才出现。窗口剩余时间及超时状态按当前请求记录计算，页面定期刷新并显示最后更新时间；服务不可达时明确显示数据可能滞后。 未配置有效通知渠道时，只提供答疑，不接受新请求。已有请求仍可查看；通知失效时暂停新接待，并向已有请求者展示触达异常和复制请求摘要的入口，不自动向第三人升级或转发内容。

## 5. 产品形态与方案选择

首版推荐浏览器入口，包含所有者工作台、同事访问页和配对申请；同事无需安装代理。接聊天工具需额外平台权限，Agent 互通需额外身份和协议设计，留待后续。局域网自动发现非首版必需，发现地址不授予权限。

### 5.1 与现有协作方式的关系

| 替代方式 | 已解决的问题 | Personal Agent 要额外验证的价值 |
|---|---|---|
| 团队 Wiki／文档库 | 保存和组织团队知识 | 按个人职责解释资料，给出可核验答案，将未解决问题转为完整请求 |
| 直接私聊本人 | 能获得判断、承诺与非结构化帮助 | 先解决重复问题，并收集背景，减少本人被打断的次数 |
| 通用文档问答 | 自然语言检索资料 | 明确代理谁、授权范围、资料责任人及本人接手路径 |
| 任务系统 | 跟踪已创建的工作事项 | 在建单前澄清需求、确认请求者意图，保留个人接待入口 |

首版差异化假设是“个人职责范围内的自然语言接待 + 请求整理与本人接手”。文档库仍是原始内容来源，代理不宣称比团队知识系统更权威。手动发布会产生副本维护成本：发布记录需保留原始来源链接和版本说明，原文更新不会被假定为自动同步；试点将复查和重新发布耗时计入维护成本。若团队现有工具已经完成该闭环，产品价值须由净节省时间证明。

### 6.1 答疑规则

回答区分资料事实（有来源可答）、资料不足（说明缺口并转交）及本人决定（任务、期限、立场交本人处理）。 来源标题、摘要和引用片段也受权限约束，不得通过引用泄露未授权资料。

回答使用结构化的“陈述 + 引用”单元。资料性事实必须包含 source_id、资料版本、片段位置；服务端检查来源存在、版本有效、权限有效及片段属于该版本。UI 可打开同一受权来源。问候、澄清问题、拒绝说明与请求状态提示不属于资料性事实，由独立类型标识；不能用这些类型承载无引用的知识答案。 结构校验不能证明语义正确。测试和人工抽检必须判断引用是否真正支持陈述，覆盖“引用存在但无关”“结论扩大”“模型混入常识”等反例；不支持的陈述算错误答案。资料不足时只说明缺口并转交，不用预训练知识补齐个人工作事实。

首版同步仅做确定性的结构、权限、来源版本及复核状态检查，不追加第二次模型调用进行语义判断。语义支持性通过离线测试和异步人工抽检验证，不阻塞当前回答，也不承诺逐条实时证明正确。完整回答生成并通过同步检查后再展示正文，期间只展示处理中状态，避免先流式泄露未经检查的内容。发送前及来源打开时重新检查授权和资料状态；已发送内容不承诺远程收回。

### 6.2 请求状态

下表是状态转换的唯一规范，展示提示不新增业务状态。 Agent 只能整理和接收；请求者确认后持久化成功即进入待本人处理，“已提交”只是回执。期望时间不是承诺；重试不重复建单。本人接受、拒绝、要求补充和提交结果，请求者补充、撤回和验收。

| 当前状态 | 操作者与动作 | 下一状态及规则 |
|---|---|---|
| 草稿 | 请求者确认提交 | 待本人处理；先校验必填字段和接待状态，持久化后返回编号 |
| 待本人处理 | 所有者接受／拒绝／要求补充 | 已接受／已拒绝／待补充；拒绝和补充须附说明 |
| 待补充 | 请求者确认提交补充 | 自动回到待本人处理，并重新开始首次处理计时；仅保存草稿不流转 |
| 待补充 | 所有者接受／拒绝 | 已接受／已拒绝，保留已知缺失项及本人决定 |
| 已接受 | 所有者提交结果 | 待验收；必须附结果说明，可附链接 |
| 待验收 | 请求者确认解决 | 已完成 |
| 待验收 | 请求者说明未解决 | 已接受，保留争议说明；不生成新请求 |
| 任一未终结状态 | 请求者撤回 | 已撤回；停止后续处理与提醒，明确已发生工作无法自动撤销 |
| 已完成／已拒绝／已撤回 | 请求者再次发起 | 原记录保持终态，新建关联请求，经确认后提交 |

终态为已完成、已拒绝、已撤回。待验收不自动变成已完成，默认第 3 天提醒请求者一次；长期未验收列入积压，不伪报完成。本人不能替请求者验收。请求提交后原始正文不可覆盖，双方通过追加消息补充；状态变更按记录版本校验，并发冲突返回当前状态要求刷新，避免覆盖他人操作。

### 6.3 知识发布与保鲜

共享资料记录是发布内容、版本及复核事实的唯一来源。必需元数据如下：

| 字段 | 创建或更新方式 | 规则 |
|---|---|---|
| source_id／version | 发布系统生成 | 稳定资料编号与不可变版本；回答绑定具体版本 |
| title／content | 所有者编辑 | 首版文本或 Markdown，容量候选值见附录 B |
| original_source | 所有者填写 | 可为链接或“本人编写”；外部链接不得包含凭证 |
| responsible_person | 所有者指定 | 首版固定为所有者，承担复查责任；不自动通知原作者 |
| published_at | 系统生成 | 当前版本发布时间 |
| last_verified_at | 所有者明确确认 | 首次发布需确认有效；仅浏览、被引用、编辑或索引重建不刷新 |
| review_interval_days | 所有者设置 | 默认 30 天，可选 7、30、90 天 |
| lifecycle | 所有者操作 | 草稿、已发布、已撤回；复核状态由规则计算 |

复查到期时间由 last_verified_at 和 review_interval_days 计算，不另存可漂移的过期标记。已发布、无未处理失效报告且未到复查时间的资料正常参与检索。资料变更必须生成新版本并确认有效，当前版本替代旧版；旧版保留作历史引用，不参与新答疑。

仅因时间到期的资料进入待复核宽限期：从到期时刻起不足 7 天仍可检索，但回答和每个相关来源强制展示“该资料最后确认于 X 天前，可能已过期”，展示具体确认日期及转交入口；混合来源按资料分别标注。到期满 7 天退出新答疑，提示建议转交本人。正常资料优先，不能静默把宽限资料当作已确认资料。

收到未处理失效报告、被证实错误、撤回或权限失效的资料立即退出检索，不享受宽限期。已有会话再次回答时适用当前规则，不能沿用旧的检索资格。所有者可确认仍有效、修订发布或撤回，记录操作者及时间。待复核采用中性说明，不使用红色或故障警告图标；已证实错误、权限异常另行明确提示。

工作台展示到期、未来 7 天到期和失效反馈清单；宽限期内每份资料在每日日汇总持续列出，直至复核或退出，避免逐条打断。未绑定邮件时仍在工作台可见，并在配置时说明缺少离站复查通知。访问者可提交“可能已失效”反馈及原因，只能影响其有权访问的资料；反馈不直接篡改正文。同一资料反馈合并，防止重复通知。 验收覆盖：到期及宽限期边界、复查后恢复、仅访问不刷新、版本替换、失效反馈、撤回和索引延迟。派生索引即使尚未更新，服务端也须过滤无效资料。超期不等于事实错误，UI 使用“待复核”。

### 6.4 请求类型与字段

公共必填字段：类型、标题（1～100 字）、“背景与希望获得的帮助”（单一多行字段，合计 1～4000 字）；请求者身份由登录身份提供，不允许模型或表单伪造。公共选填字段：期望时间、影响说明（最多 1000 字）、相关 HTTPS 链接（最多 5 条）。首版不支持附件上传，不自动抓取链接内容。

| 类型 | 额外必填字段 | 选填字段 |
|---|---|---|
| 代码／文档评审 | 评审链接、希望关注的问题 | 分支／版本 |
| 故障协助 | 现象、影响范围、已尝试步骤（可明确填写“尚未尝试”） | 脱敏错误摘要、复现步骤 |
| 联调协作 | 对接目标、当前阻塞点 | 环境、候选时间段及其时区 |
| 信息咨询 | 具体问题 | 已查阅资料 |
| 其他 | 具体诉求 | 补充背景 |

提交时类型专属字段也须完整；未知但允许缺省的内容只保存为明确缺失，不编造。必填不完整时保留草稿并逐项提示。期望时间按浏览器时区输入、同时展示时区，过去时间须修正；它不等于本人接受的截止时间。链接仅作为数据展示，拒绝脚本协议、内嵌凭证和超长输入，展示前安全转义。 提交前展示原始字段、模型摘要、缺失项和预计首次处理窗口，允许请求者编辑摘要；摘要不能替代原文。每次确认提交生成幂等键，重试返回同一编号；草稿在本机短期保留，退出登录时清理。业务状态变更必须通过权限检查后的确定性接口，模型无权直接变更。

### 6.5 请求触达与积压控制

首版只有一份经所有者显式绑定并验证收悉的邮件配置，复用于“请求通知”“访问申请通知”“知识复查通知”三个独立开关，不另建渠道配置。日汇总仅合并已启用类别；知识复查通知默认开启，请求接待要求请求通知开启且渠道健康。申请通知可独立开启，不要求先接待请求；关闭申请或复查通知不影响请求接待，关闭请求通知则暂停新接待。无验证渠道时三个开关均不可启用；通知类别默认值须在首次设置中确认。不依赖工作台角标作为唯一触达。通知默认仅含代理名称、数量、最早待处理时间和工作台入口，不含问题正文、来源或第三人个人信息。邮件外发是独立授权，不因允许云端模型而自动启用。邮件中的工作台入口是所有者确认的回环地址或其隧道本地映射地址，仅作导航、不携带凭证；仅部署主机上的受控终端或已建立主机隧道的终端可访问。其他设备点击不保证可用，邮件应同时说明需先建立隧道，不能把 localhost 自动解释为远端主机，也不回退到局域网管理地址。

- 每天所有者在配置中明确确认的 IANA 时区 09:00 汇总已启用类别的待处理请求、知识复查和未过期访问申请；无待办不发送。审批通知不得逐申请发送，申请数量合并展示。时区不跟随服务器、浏览器或出差位置自动变化；所有者可修改并预览下次发送时间。同一当地日期最多一个日汇总，夏令时缺失时刻在当日首个可用时刻发送、重复时刻只发送一次；改区不补发旧日期汇总。已发生的 24／72 小时等时长按实际经过时间计算，不随时区改变。
- 待本人处理满 24 小时，合并发送首次超时提醒；每天最多一次超时提醒，不逐条轰炸。
- 最早请求处于待本人处理滞留满 72 小时仍未处理，自动暂停新接待，通知所有者并在访问页说明。所有者处理或明确调整安排后手动恢复，恢复前再次确认通知渠道有效。
- 待补充由请求者行动，进入状态第 3 天提醒一次；待验收同理。待补充或待验收连续满 7 天起，每日列入所有者汇总滞留清单，直到状态改变；已接受超过 7 天无更新也列入。不自动关闭、不将其计入“待本人处理 72 小时暂停”条件；关闭请求通知时仍在收件箱及积压指标可见。已接受与待验收争议循环无次数上限，从状态记录计算退回次数并在双方详情展示，不自动阻止继续处理。
- 发送失败后在 5 分钟、30 分钟、2 小时各重试一次。连续失败后标记渠道异常并暂停新接待；已有请求不丢失、状态不自动改变。
- 通知发送成功仅说明邮件服务接受，不等于本人已阅读。系统不得向请求者宣称“本人已知悉”，除非本人明确操作。
- 设备恢复时，从请求状态和时间计算遗漏提醒，合并发送一次；通知回执只用于去重和重试，不复制请求状态。

所有者可主动暂停接待。若其暂停请求通知，则同步暂停新接待；已有未终结请求仍显示实际状态与触达风险。各时限是接待机制的试点默认值，不构成工作完成 SLA。通知渠道不可用时，产品以停止接收新请求兜底，不承诺必然触达本人。

## 7. 关键用户流程

1. 所有者设置身份、模型边界及共享资料，预览访问者可见内容；验证通知后才开启请求接待。
2. 同事申请访问，所有者经既有渠道核实并批准新设备会话；默认不向任何同事开放。
3. 同事提问、核验来源并反馈解决情况；未解决可编辑转交字段后确认提交，不复制整段对话。答案下提供“已解决／未解决”按钮；如尚未反馈，下次访问在 48 小时反馈窗口内合并展示一次“上次的问题解决了吗”，每轮次最多回访一次，可忽略、不阻断、不发邮件；展示只包含当前访问者自己的问题，删除会话后不再回访。
4. 本人处理请求并提交结果，请求者确认完成或说明未解决；超窗提示、触达及状态按第 4、6 节执行。

## 8. 身份、隐私与信任边界

### 8.1 授权原则

- 同一局域网不构成可信身份。
- 访问控制由服务端执行，不能仅依赖模型遵守提示词。
- 首版采用所有者维护的访问白名单和统一共享资料集；精细到人的资料授权留待后续。
- 同事身份只能访问对外代理业务接口，不继承所有者的 Gateway 管理身份、配置访问权或私人 Agent 权限。
- 私人工作资料与对外共享资料明确分开。
- 对外代理使用独立会话与记忆边界；私人身份文件、自动记忆注入、其他访问者历史和工具结果都不得进入其提示词。
- 外部消息和资料中的指令不能改变权限、身份或执行规则。

### 8.2 传输与模型边界

- 通信需要加密，并验证对端身份，具体机制由技术设计确定。
- 纯本地模式下，问题、资料和回答不发送给外部模型服务。
- 启用云端模型前，明确展示将外发的数据类别并由所有者确认。
- 不得因本地模型失败而静默切换到云端。

### 8.3 撤销与删除

- 权限变更适用于后续检索、生成和发送。
- 发送前再次确认权限；已撤销权限的生成结果不得继续发出。
- 撤回资料后，相关索引和缓存必须同步失效。
- 已被同事查看或复制的信息无法保证收回，界面需在共享时说明。
- 会话从最后一条消息起保留 30 天，到期删除正文及派生缓存。请求转交只复制请求者确认的字段，不复制整段对话，后续会话删除不影响独立请求。
- 请求从进入终态的时间起保留 30 天，期间阅读或追加记录不延长期限；自然到期时清除整个请求的正文、回复、派生副本、状态记录和身份关联，不另生成删除回执。提前删除路径的最小回执仍不得超过该原始到期时间；未终结请求不因会话过期而删除。所有者可提前删除整个请求记录的正文，请求者可删除本人的会话。请求撤回后，请求者可自助删除其提交的标题、正文、摘要、链接及自己追加的消息，无需本人批准；本人回复不属于请求者撰写的内容，保留至正常期限或由所有者提前删除。删除前明确展示影响范围，原请求不再恢复。
- 请求者自助删除清除其原文及系统生成的派生摘要、索引和缓存，并以“内容已被请求者删除”占位。首版所有者回复只写独立判断、理由与必要转述，不提供引用块、自动复制原文或模型代拟回复；提交前提示勿逐字引用请求者内容，不实现字符范围追踪。所有者独立回复保留至正常期限，不因请求者删除而整条删除；手工粘贴及转述不做语义识别，不能保证清除所有手工副本，删除确认页须先披露范围。已删除原文不再进入模型、通知或导出；既有独立回复可能保留转述，不承诺擦除已送达副本。误贴原文需所有者主动删除相应回复；精细引用跟踪在有真实需求后另行设计。
- 删除后保留最多 30 天的最小状态回执（请求编号、终态、删除时间），可含仅用于双方访问控制的内部身份关联，不含显示姓名、正文和链接；不能宣称完全匿名，期限后删除。不得借日志继续保存已删除正文。
- 被历史引用的旧资料版本在关联会话及请求保留期内仅供获权追溯，不参与新检索；撤回后不可再打开正文。没有存续引用的旧版本可清理。删除资料时清除正文、索引及缓存，历史回答只保留不可打开的来源标记。

### 8.4 身份方案与生命周期

| 候选方案 | 体验及优点 | 代价与首版选择 |
|---|---|---|
| 本人批准新设备会话 | 同事提交申请，所有者经已知渠道核实并批准 | 需本人介入；适合小团队，作为首版默认 |
| 一次性邀请链接／二维码 | 易分享、易开始配对 | 转发或抢用不能证明身份；仅建立待批准申请，不直接授予权限 |
| 企业身份登录 | 可复用组织身份、减少人工确认 | 依赖企业身份源和离职同步配置，作为后续方案 |

授权绑定人，凭证绑定该人在指定浏览器中的登录会话。申请中的自报姓名不构成身份依据；所有者通过已知企业聊天或当面核实，不新增采集身份证件。每个新浏览器／设备必须单独批准，不共享所有者配对凭证。 邀请凭据须短期有效且单次使用（候选期限见附录 B），不携带个人资料，兑换后从地址栏移除；邀请不是登录凭证。审批后的登录凭证采用浏览器安全会话机制，设置明确的绝对有效期，到期重新批准（候选期限见附录 B）；具体密钥与传输实现由技术设计确定，必须满足不可被普通页面脚本读取、不写入 URL 和日志、防伪造请求的验收要求。

所有者可查看每人的已批准设备会话、批准及最近访问时间，可撤销单个会话或该人的全部权限。换电脑重新申请；丢失设备单独撤销；离职由所有者撤销整个人并使其全部会话失效，首版不宣称自动感知离职。撤销后每个业务请求、生成结果发送和来源读取都重新受当前授权约束，不要求重启。

所有者工作台设“访问管理 → 待批准申请”，展示申请时间、声明身份和核实结果；只有已认证所有者可批准／拒绝，邮件链接只导航到该页面，不直接授权。申请者可查看自己申请的待批准、已批准、已拒绝或已到期结果。待批准申请提交后满 72 小时失效，不自动续期；日汇总只是提醒，不保证本人审批。到期后申请者可对原申请手动重新提交一次，形成关联的新申请并重新计时，不自动继承批准；第二次到期须由所有者重新邀请，不以新设备会话绕过该续提规则（原申请标识用于关联，申请限流仍有效；首版不声称能识别匿名申请人的全部换端行为）。已拒绝或已撤权者不得用续提恢复权限。申请页展示到期时间、剩余期限及结果，提供既有渠道联系说明，不暗示已通知成功。申请入口限流并限制待批准总量，超限不调用模型；限额候选值见附录 B。不向未授权访问者枚举同事身份或请求内容。需测试代理转发来源地址不能伪造。申请通知渠道可单独启用，不要求先开启请求接待；未配置时明确提示仅能在工作台审批。

### 8.5 所有者认证与恢复

所有者是掌控部署设备本地操作系统账户的人，首版不支持通过访客申请成为所有者。所有者控制面只绑定回环地址，远程管理需经已认证的主机隧道；同事局域网入口不得转发任何管理路由。首版复用 ZeroClaw 本地配对引导及原生配对 Bearer 的 operator 解析，配对码只在本人控制的终端取得，配对本身须受限流与短期单次约束。用于签发配对码的进程级 admin token 与配对后 operator Bearer 是两种凭证，不能混用，也不提供给访客。

所有者浏览器登录必须采用安全会话存储、防伪造请求、不在 URL／日志中传递凭证，服务端按当前权威凭证状态授权；必须显式登出、撤销全部设备及设置绝对有效期（建议 8 小时，候选值见附录 B）。绝对到期需在服务端权威验证处同时约束原始 Bearer、派生浏览器会话及相关管理入口，不能只过期页面 Cookie 留下可用 Bearer。现有配对撤销可复用，不能据此假定已具备时间到期能力；若尚缺则是实现前置工作，不能绕过验收。正常到期或登出后，所有者从可信部署主机终端重新发起本地配对，取得新的短期单次配对码，再在回环地址或已建隧道的工作台重新配对登录；旧凭证不得续命或用于无感刷新，所有者重配对不影响访问者权限。凭证疑似泄露时改走下段恢复流程。首版不承诺多因素认证。

operator 凭证泄露可能暴露该 ZeroClaw 实例全部管理能力，包括访问、发布、删除及配置变更，风险不局限于 PRD 业务页面；主机影响还受进程账户和工具权限约束，不宣称凭证只限对外代理。恢复从可信本地终端暂停对外入口、撤销并持久化全部受影响凭证及会话、轮换配对码管理 admin token，再重新配对；须验证重启后旧凭证仍不可用。不能仅生成新配对码而保留旧 token；已泄露内容无法收回。实例隔离及最低主机权限仍按第 15 节执行。

## 9. 数据与状态归属

遵循单一事实来源，避免多个界面或缓存保存互相冲突的业务状态。

| 数据 | 唯一事实来源 | 使用原则 |
|---|---|---|
| 所有者身份与能力范围 | 所有者配置 | 页面与代理介绍从配置生成 |
| 访问者身份与权限 | 身份及授权记录 | 每次请求解析当前授权 |
| 共享内容 | 所有者发布的资料 | 检索索引为可重建派生数据 |
| 请求与状态 | 请求记录 | 收件箱、通知和统计从记录生成 |
| 本人授权的回复 | 确认后的回复记录 | 保留发送结果，避免重复发送 |
| 资料版本、责任人与确认记录 | 共享资料发布记录 | 新鲜度从确认时间与复查周期计算，不以点击或引用次数替代 |
| 通知投递及重试回执 | 通知投递记录 | 仅用于去重、重试和渠道健康判断；请求状态仍从请求记录读取 |

Agent 的推断不得自动写成个人事实、长期记忆或新增授权。

## 10. 异常体验

离线、超时、排队满和保存失败均明确告知，不显示成功；保存失败保留草稿，重试返回原编号。模型不可用仍可表单提交。资料不足／冲突按第 6.1 节处理，到期按第 6.3 节降级；无可用知识与接待关闭同时发生时，提供复制问题摘要及使用身份卡片中所有者主动公开的工作联系说明；未公开时仅提示使用双方已知渠道，不推断或暴露私人联系方式。撤权停止发送，通知异常暂停新接待，未解决验收退回处理；不得用模型拒绝文字代替服务端访问控制。

## 11. 非功能需求

- **授权容量：** 每实例最多 5 名已授权访问者，按人而非设备计数，所有者不计入。满额时新的人员批准操作失败并明确提示“访问名额已满”；不自动排队批准。已授权人新增设备不占新人名额，撤销整个人后释放；并发批准须原子检查，最多只能有 5 人生效。
- **响应体验：** 区分提交反馈、排队、生成和校验；超过公开答疑期限明确失败，不伪报成功。正文只在同步确定性检查后整体展示，语义抽检异步进行。
- **公平性：** 按已认证访问者身份跨设备聚合，采用访问者间轮转、同人先进先出的公平调度；已运行任务不抢占。同人最多一个运行任务、两个排队任务，不允许通过多会话占满队列。
- **队列容量：** 同人最多两个排队位是上限，不保证可连发两条。同人第二个排队任务不得占用其他已授权访问者的首个保留位；有其他人等待时不得连续调度同人。新访问者加入前重新校验容量，不能静默破坏已公开的公平规则。
- **过载与取消：** 展示等待、超时、取消及重试入口；排队和检查计入总期限。到期移出队列，运行任务取消或隔离迟到结果，重试不重复生成；请求表单不依赖模型队列。
- **可靠性与控制：** 请求持久化成功才返回成功；重启不丢失。所有者可暂停服务、撤权和删除资料。
- **可追溯性：** 保留回答来源版本及授权操作记录，内容删除规则优先于诊断便利。

五人授权上限是产品约束，工程等待容量必须支持每人首个保留位；若不能满足则不能启用该配置。硬件、模型、执行并发、资料容量和耗时数值为[附录 B](personal-agent-delivery.md)的技术验证候选值，不是冻结承诺；技术设计须验证公平容量约束，固定测试基线并报告实际结果后冻结。公平调度保证调度机会，不保证每个长任务都能在期限内完成。

## 12. 验证计划与成功指标

建议先用 **3 至 5 名所有者及其协作同事开展两周试点**。每实例最多 5 名已授权访问者，不因试点配置而放宽。试点前记录一周重复答疑次数和估计耗时，作为基线。

| 指标 | 定义 | 首轮目标 |
|---|---|---|
| 明确已解决率 | 全部已满 48 小时的有效问题中，在提交后 48 小时内明确确认解决、无需找本人且复盘未发现错误的问题占比；未反馈计入分母 | ≥40%，须结合未反馈率及抽检解读，不单独判为答案质量 |
| 未反馈率 | 满 48 小时仍无解决反馈的有效问题／全部已满 48 小时的有效问题；同时报回访展示覆盖率 | 首轮观察项，无预设通过阈值；缺失反馈不当作错误答案，超过窗口的反馈单列 |
| 答案抽检正确率 | 每位所有者每周随机抽查至少 10 条事实回答，不足则全查；全部事实均被有效来源支持才算正确 | ≥90%，同时报告样本量 |
| 被纠正率与复核覆盖率 | 已复核事实回答中，被所有者确认需实质纠正的回答占比；另报复核覆盖率及资料错误、模型错误、混合、待定位四类归因 | 纠正率 ≤10%；覆盖率 ≥20%，小样本不足 10 条时全查 |
| 资料未到期率 | 当前已发布资料中未到复查期限的比例，按日记录；失效报告另计，不用时间代替正确性 | ≥90%，为维护纪律目标，未达标不直接判定产品失效 |
| 资料宽限占比 | 已到期不足 7 天、无失效报告且仍获准检索的资料／全部已发布资料；同时报被排除数量及高频问题覆盖 | ≤20%，为降级程度目标，不以宽限计作未到期 |
| 宽限答案占比 | 含至少一个宽限来源的事实回答／全部事实回答；多来源回答只计一次 | 报告每日及全试点比例，无预设质量阈值；宽限标注覆盖率 100%，超过宽限或失效资料使用量为 0 |
| 首次处理及时率 | 待本人处理请求中，在公开处理窗口内由本人接受、拒绝或要求补充的比例 | ≥90%；自动回执和提醒不算处理 |
| 请求积压 | 按状态报告数量、最老等待时间及超窗口比例；待验收不计为已完成 | 超时触发提醒及暂停规则覆盖率 100% |
| 请求完整率 | 本人认为无需再次索要基本背景的请求占比 | ≥80% |
| 重复打断变化 | 与基线相比的重复答疑次数变化 | 下降 ≥25% |
| 所有者净节省时间 | 与基线相比节省的沟通时间，扣除资料发布／复查、答案抽检／纠错、通知和请求管理耗时；日终一次自评三个数字：省下分钟／维护分钟／纠错分钟；净值为前者减后两者，维护含复查、抽检、通知与请求管理，纠错不重复计入维护；漏记标缺失、不补零，无需计时器 | 为正；单列隧道建立／重连、所有者再认证的次数与耗时，计入维护分钟，观察是否抵消收益 |
| 持续使用意愿 | 愿意继续使用的所有者占比 | ≥60% |
| 越权披露与未授权承诺 | 试点发现的事件数 | 0 |

比例的分母为 0 时显示“不适用”及样本数，不补零。资料维护指标报告每日趋势、复查日及所有者休假背景，不能用全量同时到期的一天推断用户价值归零；维护与降级目标超限应触发复盘，产品效果由回答质量、解决反馈和净收益共同判断。回访覆盖率分母为窗口内再次访问且有未反馈问题的人次，分子为实际展示回访的人次；未再次访问不伪算漏发。试点结束后等最后一批问题满 48 小时再冻结反馈指标。以上为产品假设，不代表已达到的效果。小样本数据需结合访谈和实际对话复盘判断。

有效问题排除事先标记的演示、压测及重复重试，不能事后排除答错、拒答和超时的问题。状态查询和问候不计为知识问题。主动举报的问题全部复核，但与随机抽检样本分开报告，避免样本偏差。复核指标按实际样本计算，不将“无人纠正”当作正确。汇总只记录编号与计数，不另建含问题正文的分析数据副本。资料错误指来源内容本身错误或过时，模型错误指来源有效但被曲解、扩大或无依据补充；无法区分标为待定位。两类均计入总纠正率，不能借归因排除错误样本。共享内容被授权发布不代表事实必然正确；未来引入多人维护或同步前须另评审来源准入及投毒风险。

## 13. 发布验收门槛

发布必须通过[附录 A](personal-agent-acceptance.md)的 A01 至 A23，覆盖身份、资料、请求、触达、删除及公平性。结构校验与离线语义评测分别验收，不能互相替代；未固定技术基线前不得声称性能达标。

## 14. 迭代路线

| 阶段 | 交付重点 | 进入下一阶段的条件 |
|---|---|---|
| 场景验证 | 少量授权资料，人工辅助复盘 | 重复问题足够多，同事愿意先问代理 |
| MVP | 身份配对、资料复查、可核验答疑、请求验收、兜底通知、撤权及指令隔离 | 完成验收，所有者净节省时间为正；单列隧道建立／重连、所有者再认证的次数与耗时，计入维护分钟，观察是否抵消收益 |
| 协作增强 | 未读角标、聊天工具接入、细粒度权限 | 有持续使用和明确接入需求 |
| 代理协作 | Agent 间请求转交、时间协调 | 身份与授权机制稳定，可追溯 |
| 有限自主执行 | 特定低风险操作 | 每类操作有明确授权、撤销和责任边界 |

## 15. 待确认事项

以下均有建议默认值，但需试点负责人确认后才能冻结技术方案和排期：

| 决策 | 推荐倾向 | 影响与替代条件 |
|---|---|---|
| 部署载体 | 每位所有者独立实例，放在局域网常在线设备或隔离环境 | 能在本人离线时继续服务；个人电脑可用于演示，但休眠时服务不可用。共享宿主必须隔离数据、进程权限和凭证，不以多 Agent 别名代替系统隔离 |
| 首批用户 | 研发团队，每实例最多 5 名已授权访问者 | 请求枚举围绕评审、故障、联调；换用户群需重新验证字段与基线 |
