Constants§

ANY_KEY
A RetiredKey::path segment that matches every key of the table at that level, e.g. &["agents", ANY_KEY, "max_tool_iterations"] retires the key in every [agents.<alias>] block.
CAPPED_KEYS
Every key lowered to a maximum on load. A stored value above max is lowered to max with a MigrationNotice::Lowered, by the migration chain and again on every load of a current config, the way RETIRED_KEYS drops a retired key: a file written before the maximum existed keeps loading, and its value changes in the open instead of failing validation. Values at or below max, and values that are not integers, are left for deserialization and validation to judge.
CURRENT_SCHEMA_VERSION
The schema version this binary writes and expects on disk.
INFERRED_SCHEMA_VERSION
The version a config with no schema_version key is read as when its layout is plainly V3: it holds a section only the V3 layout has, and nothing only an older layout has (see unversioned_shape).
RETIRED_KEYS
Every retired key, applied by the migration chain when it reaches retired_in, and again on every load of a current config so a key that reappears is dropped with a notice rather than silently ignored. Retiring another key is one entry here plus removing its schema field, its reason in every locale’s cli.ftl (unless it shares one), and a version bump (a new MIGRATION_STEPS entry) if no pending version already covers it.
SECURITY_CRITICAL_KEYS
Top-level keys whose silent loss could weaken security posture: dropping a malformed one to its Default may grant a broader posture than intended. Salvage still drops them (so the daemon boots) but logs ERROR and reports them in ResilientLoad::dropped_security for exposure gating.

apply_retired_keys_to_doc
Apply every retired key, through the current schema version, to an on-disk document in place. This is the same RETIRED_KEYS policy the migration chain applies to a parsed value, used where a file is edited rather than rewritten (an incremental save). Only retired keys change: comments, formatting and every other entry, including ciphertext, are left byte for byte. All three spellings are handled ([a.b] headers, dotted keys and inline tables). Returns what changed, for the caller to report once the file is safely written.

keep_version_backup
Keep a complete copy of config_path, as it is now, beside it, and return the copy’s path when this call wrote it. A kept copy is never replaced or removed, so the original of each version survives every later migration and save. Because it lasts and can hold the plaintext secrets of keys the migration retires, it is owner-only (0600 on Unix) whatever the mode of the file it copies.
lower_capped_keys_in_doc
lower_capped_keys over an on-disk document, for the paths that edit a file in place, the way apply_retired_keys_to_doc retires keys there. Only the lowered value changes; its comments and every other byte stay. Returns what changed, for the caller to report once the file is written.
