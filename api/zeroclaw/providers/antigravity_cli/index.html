Module antigravity_cli 

Expand description

Antigravity CLI (agy acp) subprocess model provider.

Every inference request spawns agy acp, the Agent Client Protocol stdio server shipped with Google’s Antigravity CLI, and runs one bounded one-shot ACP exchange: initialize → authenticate → session/new → session/set_model → session/prompt. The prompt travels as JSON-RPC on child stdin; it is never placed in argv or a temporary file.

§Usage

[providers.models.antigravity_cli.default]
model = "gemini-3.8-flash-high"
working_directory = "/path/to/agents/default/workspace"
api_key = "..."                      # set with `zeroclaw config set`
# auth_method = "gemini_api_key"     # default
# binary_path = "/home/you/.local/bin/agy"

[agents.default]
model_provider = "antigravity_cli.default"

§Authentication policy

ZeroClaw is an outer harness: it injects its own system prompt and owns the conversation. Google’s current Antigravity terms (FAQ, Terms §6, and staff guidance on the Google AI forum) permit only API-key, Agent Platform, and Gemini Enterprise sign-in for such harnesses. Accordingly:

  • gemini_api_key (default) sends this alias’s typed api_key secret in the ACP authenticate _meta.apiKey field. The key never appears in argv or the child environment, and GEMINI_* passthrough is rejected.
  • agent_platform authenticates with Application Default Credentials.
  • oauth_business is an explicit opt-in that reuses a Gemini Enterprise sign-in cached in this alias’s isolated state directory. The session is refused unless Antigravity reports a business tier.
  • oauth_personal is refused when the provider is built.

Every alias runs with its own --gemini-dir, so a personal sign-in cached in ~/.gemini can never be picked up, including by Antigravity’s fallback to a saved login when an explicit method has no credential.

§Host-side trust boundary

The child is a tool-capable agent outside ZeroClaw’s native tool approval path. The shared acp_cli plumbing therefore requires an explicit absolute working directory, clears the inherited environment, bounds every ACP frame and stream, rejects permission requests unless the alias passes --dangerously-skip-permissions, and terminates the child process group (Unix) or Job Object (Windows) on every exit path. Public errors never include child stderr or raw ACP frames.

§Limitations

  • Only the system prompt (if present) and final user message are forwarded. The system prompt uses Antigravity’s _meta.antigravity.systemPrompt.append session extension.
  • The provider is one-shot; ACP sessions are not resumed.
  • Native ZeroClaw tool calls are not emitted; ChatRequest.tools is ignored.
  • Token usage is not reported (ChatResponse.usage is None).
  • Only temperatures 0.7 and 1.0 are accepted because agy acp has no sampling control.
  • timeout_secs is clamped to one hour maximum.
