Module dashboard_session 

Expand description

Opt-in dashboard sign-in sessions ([gateway.dashboard_sign_in]).

A browser that completed an OIDC sign-in holds only an opaque session cookie. The access token it was issued stays here, in memory, and every request carrying the cookie is checked again against the same inbound authority RPC uses: credential expiry, the introspection revalidation deadline, and the grants the principal holds under the policy in force now. The gateway decides nothing of its own; it only narrows.

The layer never rejects a request itself. It classifies the caller and leaves the decision to the route: public routes ignore the classification, so an expired cookie never keeps the dashboard shell or the sign-in screen from loading, while every authenticated route reads it through current_caller or the request’s DashboardCaller extension.

With sign-in off, which is the default, the layer is a no-op that never reads a cookie: a forged one is no credential at all.

The store is process-shared rather than held in AppState. The gateway is rebuilt on every daemon generation, and a sign-in has to survive a reload; a session verified by an earlier generation’s authority is verified again, with the token it holds, against the current one before it is used.
