Module dashboard_core 

Expand description

Signed-in dashboard sessions on the core.

A scoped dashboard session chats through the core’s session methods. Each chat socket opens an RPC connection of its own through the daemon’s in-process connector, presenting the token the session signed in with, so the core sees that principal, applies that principal’s grants, and keeps the conversation under that principal. The gateway translates the dashboard’s routes and decides nothing the core does not; where it narrows (the agent list), it only removes. An administrator keeps the in-process chat and its history.

Each socket is one conversation (CoreChat): created when the socket opens, and closed when it closes, when the session ends (sign-out, expiry, revocation) or with the daemon generation. No other socket reopens it, so nothing about a conversation is shared between sockets: not its connection, not the TUI identity the core holds it under, not its approvals. A dashboard session may have MAX_LIVE_CONVERSATIONS chats open at once (CoreBinding).

A conversation the core finishes creating long after its chat gave up is closed when the core’s answer lands. What a chat cannot close (its token no longer verifies) is left to the core, which retires a conversation whose client has stayed away for wss.orphaned_session_timeout_secs. A chat’s identity is never presented again once the chat is over, so its conversation is such an orphan.

Callers without a dashboard session, and every request when this gateway does not run inside the daemon, are served exactly as before.
