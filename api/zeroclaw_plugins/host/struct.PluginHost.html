pub fn install(&mut self, source: &str) -> Result<String, PluginError>

Install a plugin from a directory path. Returns the installed plugin’s manifest name so callers can key follow-up work (config seeding, messaging) off the canonical name rather than the source path.

This is Self::admit_source followed by Self::install_admitted. A caller that wants to load-check the component in between (the CLI’s install-time verification) calls the two halves itself; either way, the bytes that were admitted are the bytes that get installed.

pub fn admit_source(&self, source: &str) -> Result<AdmittedSource, PluginError>

Admit a source without installing it.

Parses and signature-checks the manifest, validates its shape and config, refuses a name the host has already loaded, and reads the component once through the same confined, size-bounded, digest-checked admission the host applies to installed plugins. Everything Self::install_admitted persists comes from the returned AdmittedSource and never from source again, so whatever a caller verifies between the two calls is, byte for byte, what gets installed.

The duplicate-name check runs before the component is read, so a package the host would refuse anyway never reaches the loader.

pub fn admit_update( &self, name: &str, source: &str, ) -> Result<AdmittedSource, PluginError>

Admit a source as the replacement for the installed package name.

This is Self::admit_source with the identity decided the other way round: name must be loaded, which is checked before the source is opened, and the source’s manifest must name it, which is checked before the signature and before the component is read. Everything else, from signature policy to the one confined read of the component, is the same admission a new package gets.

pub fn remove(&mut self, name: &str) -> Result<(), PluginError>

Remove a plugin by name.

For a loaded plugin, the directory it was loaded from, which need not be named name, is claimed under the package lock and deleted through the claim once it proves to hold the generation this host loaded; a claimed generation that does not is put back and refused as PluginError::NamespaceChanged. A claim this cannot settle, because that put-back or the delete fails, is reported as PluginError::RecoveryRetained. The claim records only name, so the next remove of name puts what it holds back at name, not in the directory it came from, and refuses while something occupies name. Claiming needs the atomic no-replace move install and recovery use, and refuses where the platform or filesystem has none. For a name the host did not load, remove is the recovery path for an interrupted install: it claims and validates the exact directory generation and cleans only staging whose protocol lease proves abandonment. Ambiguous legacy staging is retained. The final directory must be empty, or hold a manifest.toml naming name and nothing an install never writes, with admission rejecting its own contents rather than its signature. That includes a package this host cannot accept as written, such as one whose component exceeds the admission size limit. Anything else at the name is left untouched and reported as PluginError::UnadmittedPackage with the reason: a symlink or file, a directory holding files but no manifest, one holding anything an install never writes or whose manifest names another package, one that cannot be identified, inspected, or listed, a loaded package’s directory, a package admission accepts, and one this host rejects for its signature policy. A refusal restores the claimed package without replacing a concurrent occupant that holds files; if restoration cannot complete, RecoveryRetained names the retained transaction and a later remove retries it.

impl PluginHost

Updates: replacing an installed package with an admitted source, and recovering what an interrupted replacement left.

Every step runs under the package lock that serializes install, remove and recovery across hosts. The replacement is built in a leased stage, as install builds a package, and the installed generation is claimed into a leased transaction of its own before the replacement is published in its place. Both moves are renames that never overwrite, and a claimed generation is deleted only through its own handle. Discovery ignores the hidden transaction directories, so neither a half-built replacement nor a claimed generation is ever loaded, and a lease that outlived its process is how recovery tells an interrupted update from one still running.

Source

pub fn update_admitted( &mut self, admitted: AdmittedSource, ) -> Result<ReplacedPackage, PluginError>

Replace the installed package that admitted names.

admitted comes from Self::admit_update. The replacement is staged as Self::install_admitted stages a new package, and the staged skill bundle of a skill-capable package is validated as discovery will validate it: staging copies no symbolic links, so a bundle admission accepted can stage incomplete. Only then is the installed generation claimed. If its manifest text or admitted component differs from the generation this host loaded, it is published back and the update refused, because the caller compared authority against the generation it loaded. The replacement is then published in the directory the installed package was discovered in, and if that fails the claimed generation is published back. So on every error except PluginError::ReplacementInterrupted the installed package is exactly as it was.

Configuration and durable state are not touched: they belong to the instance identity, which does not include the version.

§Preconditions

This method does not compare authority. The runtime grants a plugin what its manifest requests, so before calling it the caller must compare the authority admitted requests (its permissions, capabilities, provides ids and publisher) with the generation this host loaded, and have the operator accept any increase. What this method guarantees is that the generation it replaces is the one that comparison was made against.

§Errors
  • PluginError::NotFound when no package of that name is loaded.
  • PluginError::NamespaceChanged when the installed package is not the generation this host loaded, or the plugins directory changed. The installed package is put back first.
  • An I/O error when the package lock is still held after 60 seconds, or when staging, claiming or publishing fails, and PluginError::InvalidManifest when the staged skill bundle is not what discovery would load. The installed package is untouched or put back.
  • PluginError::ReplacementInterrupted when the claimed generation could not be put back either. It names where that generation is preserved, and this host no longer holds the package as loaded.

pub fn recover_interrupted_update( &mut self, name: &str, ) -> Result<UpdateRecovery, PluginError>

Put back a package an interrupted update left claimed, or delete the generations finished updates left behind.

Runs under the package lock and judges only replacing transactions whose lease it can take: a lease still held belongs to a process that has not finished, and its claimed generation is never touched. Whether the package is installed is judged from the plugins directory as it is under the lock, not from this host’s earlier view, which can predate the update that left the claims. Only name is judged again, and every other package keeps this host’s earlier view, so a batch that recovers each of its names does not admit every installed package once per name. When it is installed, every claimed generation of it is out of date, so each is marked for deletion and deleted through its handle; one that cannot be is reported and left. When it is not, the one generation an interrupted update claimed is published back to <plugins_dir>/<name>, so the restored package is admitted only if the configured policy accepts it, like any other. An installed package of the name takes precedence over any claimed generation. Several claimed generations, or anything already at the name, are reported and left as found; a generation marked for deletion is never put back; and a claim that holds neither is finished. Stages that interrupted updates of name left are swept as remove sweeps them. A batch that did not name the package calls Self::sweep_interrupted_update instead, which never puts one back.

Source

pub fn sweep_interrupted_update( &mut self, name: &str, ) -> Result<UpdateRecovery, PluginError>

Self::recover_interrupted_update for a batch that did not name the package. Generations finished updates left are deleted the same way, but a package an interrupted update displaced is left where it is and reported as UpdateRecovery::Displaced, so only recovering it by name puts it back. That is judged under the lock, so a package displaced after the batch chose its names is left in place too.

Source

pub fn displaced_packages(&self) -> Result<Vec<String>, PluginError>

Packages an interrupted update left claimed: sorted names that are not loaded and have an abandoned claim that holds a package. Self::recover_interrupted_update puts such a package back, or, with several claims or an occupied name, reports why it cannot. Runs under the package lock, so it never holds a claim’s lease while a recovery judges it.
