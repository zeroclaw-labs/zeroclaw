Expand description

The merged authorization result for one principal: what it may touch and how. Produced by the shared grant resolver from permission profiles at a specific authorization-policy generation; consumed by dispatch classification, the gateway router, and deep resource checks. Never stored on a Principal — consumers re-resolve when the generation changes.

§admin: bool

Full access to everything. Short-circuits all other checks. An explicit administrator grant dominates the ordinary grant set.

§allowed_agents: Vec<AgentAlias>

Agent aliases this principal may bind or address. Empty = none; broad access requires the explicit WILDCARD entry.

§config_write_paths: Vec<String>

Dotted config path prefixes this principal may write. A trailing .* grants the subtree; a bare path grants that exact prop; the WILDCARD entry grants every path. Empty = none.

§allowed_tools: Vec<String>

Tool names this principal may cause an agent to run. Empty = none; broad access requires the explicit WILDCARD entry. (The agent’s own tool policy still applies on top.)

§resources: BTreeMap<Resource, BTreeSet<Verb>>

Resource-class grants: which verbs are permitted per resource. Missing resource = deny.

pub fn may_use_agent(&self, alias: &str) -> bool

Whether this principal may bind or address the given agent alias. An empty selector list grants no agents; broad access requires the explicit WILDCARD entry or admin.

Source

pub fn may_use_tool(&self, tool: &str) -> bool

Whether this principal may cause the named tool to run. An empty selector list grants no tools; broad access requires the explicit WILDCARD entry or admin.

Source

pub fn may_write_config(&self, path: &str) -> bool

Whether this principal may write the given dotted config path. A granted foo.* covers foo itself and every descendant; a granted bare foo.bar covers exactly that prop; the WILDCARD entry covers every path. Empty = none.

Source

pub fn merge(&mut self, other: &Self)

Merge another grant set into this one — the deterministic monotonic union used when one identity maps to multiple permission profiles. No implicit deny rules, no profile-order precedence; admin from either side dominates.
