## Why

PRD v0.6 描述了一个局域网内的个人代理：回答重复工作问题，收集完整协作请求，同时不暴露私人上下文或自行作出承诺。ZeroClaw 已有模型提供方、配对、Agent 执行和仪表盘，但尚无本产品的访问者身份、已发布知识生命周期、协作请求流程和通知保障。

## What Changes

- 在显式启用、单所有者的实例中交付 PRD 全部 P0 功能，最多五名获权访问者；所有者控制面绑定回环地址，访问者使用独立 TLS 监听器。
- 增加按人授权、经批准的浏览器会话、到期邀请、所有者再认证和凭证泄露恢复，不向访问者发放原生 operator 凭证。
- 增加显式发布、版本化知识，支持复查期限、仅时间到期适用的七天宽限期、失效反馈隔离、引用和当前授权检查。
- 通过 ZeroClaw 已有运行时入口执行隔离且有界的答疑，增加确定性输出校验、按人公平调度、取消、反馈和离线语义评测。
- 增加结构化协作请求、所有者决定、请求者验收、幂等、并发检查、保留及自助删除。
- 增加一份已验证的邮件绑定及三个类别开关，支持固定时区汇总、重试、超窗可见性、滞留报告和失败时关闭接待。
- 提供所有者与访问者 Web 流程、本地化文案、运维文档、PRD 验收证据和试点度量。
- P1 自动发现、未读角标、Agent 间转交、聊天接入、任意动作及另行讨论的工作进度模块不纳入本次 MVP。

## Capabilities

### New Capabilities

- `personal-agent-access`：显式启用部署、所有者认证、访问者审批、凭证、容量和传输隔离。
- `personal-agent-knowledge`：发布、版本、来源元数据、复查／宽限资格、反馈及受权来源。
- `personal-agent-answers`：隔离答疑、引用、调度、输入预算、反馈及提示注入边界。
- `personal-agent-requests`：请求表单、状态机、所有者决定、请求者验收及并发。
- `personal-agent-notifications`：邮件验证、独立开关、时区、重试、滞留及接待门控。
- `personal-agent-retention`：会话、请求、删除范围、派生数据及回执到期。
- `personal-agent-pilot`：身份展示、本地化界面、正确性复核及效果度量。

### Modified Capabilities

无。`openspec/specs/` 尚无基线能力规格。虽然没有可修改的既有 OpenSpec 文档，显式启用模式下的所有者原生凭证生命周期变更仍须实现及兼容性测试。

## Impact

拟涉及新增 `zeroclaw-personal` 领域 crate、网关传输适配器、配置／配对权威机构、根应用组装和分离的 Web 入口。按需复用 SQLite、现有模型提供方和 Agent 契约、共享 TLS、配置秘密、日志及 SMTP 库；不在运行时新增业务子系统或私人记忆存储。新增 API、模式迁移、凭证、邮件外发、保留及监听边界须有针对性的安全和用户边界测试。默认安装保持未启用且绑定回环地址。

**激活影响：** 启用 personal 模式会使实例内所有缺少可信签发／到期元数据的原生配对凭证失效，包括所有者私用助手设备及 CLI 客户端，不只是 personal Web 会话。这些客户端必须在本地重新配对；新原生凭证随后共同受有限有效期策略约束。激活确认前必须披露实例级登出和恢复步骤；禁用或回滚不得复活失效凭证。

按仓库 RFC 流程，本变更属于新子系统／安全边界。设计与任务要求在生产实施前形成持久化 RFC 决策；OpenSpec 产物齐备不等于 RFC 批准。本提案不执行外部 issue、PR、消息、部署或功能实现。
