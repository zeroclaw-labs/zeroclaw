插件发布验收

第一方插件要通过发布验收，需要满足两点：运维人员能在已发布的 zeroclaw 二进制文件上按名称安装该插件，且机器上无需 Rust 工具链；并且能够证明实际完成工作的是该插件，而不是内置功能。本页是这一验证的操作手册，也是证据模板。文中以 Discord 渠道插件为示例。若换成其他包，请替换其名称、别名、必需的配置键和目标地址。

一次运行只能证明某个软件包版本在已发布的宿主程序某个构建版本上的表现。它不能说明其他目标、其他宿主版本，或负载下的行为。

运行时机

在本次发布完成且包版本已进入注册表之后运行，针对本次发布声明支持的每个包版本各运行一次。当任一侧发生变化时再次运行：出现新的包版本，或宿主发布了改变插件接口的新版本。

开始之前

  • 产物。 一个已发布的 zeroclaw CLI 压缩包，面向 64 位目标平台，其插件宿主会编译 .wasm 组件。请先参考 发布产物验证 进行检查。在全新容器中使用 x86_64 Linux 压缩包，是展示未涉及任何工具链的最简单方式。
  • 干净的机器。 没有 Rust 工具链，也没有早前运行遗留的任何配置。
  • 平台测试账号。 对于 Discord，需要一个专用的机器人应用，部署在小型测试服务器中，绝不能使用生产环境机器人；开启 Message Content Intent，并将机器人邀请进服务器（参见 Discord 快速入门），另外还需要一个供测试人员使用的第二个 Discord 账号。测试结束后，计划重置机器人令牌。
  • 模型提供方。 任何已配置的提供方均可使用。使用脚本化的本地提供方可以让智能体的回复可重复。
  • 一份证据文件。 复制证据模板，并在推进过程中逐步填写。

只能在被遮蔽的 zeroclaw config set 提示符处输入机器人令牌。切勿将其写入文件、放在命令行中、保存到 shell 历史记录里、出现在截图中，或记入证据材料。

1. 记录环境

command -v cargo rustc || echo "no Rust toolchain"
sha256sum zeroclaw-<target>.tar.gz
zeroclaw --version
zeroclaw plugin search discord

记录归档文件名与摘要、版本字符串，以及安装所解析的注册表条目：其名称、版本、归档 URL 和 sha256。

2. 按名称安装并绑定实例

zeroclaw plugin install discord --channel-alias acceptance --egress declared
zeroclaw config set plugins.entries.zpi1_WyJkaXNjb3JkIiwiY2hhbm5lbCIsImFjY2VwdGFuY2UiXQ.config.bot_token
zeroclaw config set plugins.enabled true
zeroclaw plugin info discord

安装时会打印绑定信息以及已授予的主机。plugin info 必须报告该软件包可以在此主机上加载，并且上方的实例键存在。然后手动执行：

  • 将 plugin.acceptance 添加到一个已启用智能体的 channels 中；
  • 添加一个对等组，其 channel = "plugin.acceptance"，并且其 external_peers 包含测试人员的数字 Discord 用户 ID。

Discord 页面对这两项都有说明。请勿在任何位置配置 [channels.discord.<alias>] 表，然后启动守护进程。保留一份 config.toml 副本作为证据；其中的机密信息保持加密状态。

3. 实际测试插件

按顺序完成模板中的各项，并记录你观察到的情况，包括任何意外情况。下文提到的日志记录位于守护进程的结构化日志中，仪表盘的“日志”页面和 GET /api/logs 读取的就是该日志（参见可观测性）。全程使用合成的消息文本。

发布前请先脱敏

channel inbound message 和 reply delivered 记录包含消息文本和发送者的用户 ID。在发布任何内容之前：

  • 将用户、服务器和频道 ID 替换为占位符；
  • 仅保留合成消息文本；
  • 将配置副本中的每个 enc2: 值替换为 <encrypted>；
  • 裁剪截图，仅保留待测试的消息。

令牌绝不能出现在证据中，无论是否已脱敏。

发布证据

在本次发布的跟踪问题中发布以下内容：产物名称和摘要、zeroclaw --version 输出、注册表条目和软件包版本、步骤 1 和 2 中使用的确切命令、填写完成的表格，以及自上次通过验收的运行以来修改了该软件包或宿主的拉取请求链接。

清理

  1. 停止守护进程并运行 zeroclaw plugin remove discord。删除操作会保留实例的 [[plugins.entries]] 条目及其 [channels.plugin.acceptance] 绑定，并会输出这两项；请手动删除它们。
  2. 在 Discord 开发者门户中重置机器人令牌，使本次运行中使用的令牌失效。
